- 提问（Q11）：脱离项目解释一下 `Stream`
- 答复要点：`System.IO.Stream` 是「有序字节序列」的抽象基类，本质是增量式的"字节传送带"，既不等于"文件"也不等于"网络"。四个核心知识块：① **四条契约**——`Read` 返回 0 才表示结束（返回值小于请求量是常态）、`Write` 成功≠落盘（要 `Flush`）、包装流必须传 `leaveOpen`、Stream 非线程安全；② **两个正交维度**——能否 `CanSeek`（`NetworkStream`/`SslStream`/`GZipStream` 都不能）、终端流 vs 装饰流（可层层嵌套，`FileStream → BufferedStream → GZipStream → CryptoStream`）；③ **家族谱**——存储 / 网络管道 / 装饰 / 控制台 / `Stream.Null`；④ **现代替代** `System.IO.Pipelines`，解决 Stream 的两个限制（必须把数据拷进自己的缓冲区、同一时刻只能有一个待处理的 `ReadAsync`）

- 提问（Q12）：server 里为什么也有 `TcpClient`
- 答复要点：服务端的 `TcpClient` 不是 `new` 出来的，而是 `TcpListener.AcceptTcpClientAsync()` 的返回值（内部 `new TcpClient(acceptedSocket)`）。TCP 三次握手后两端对称，"客户端/服务端"只是谁先 `connect()` 的行为差异，不是类型差异；`TcpClient` 的真实含义是「一条已建立连接的持有者」，只是 `Socket` 的门面（`GetStream` / `NoDelay` / `Client`）。顺带发现一处不对称：`ClientSession.Close()` 只调 `_tcp.Close()` 没有先 `Shutdown(Both)`，在 `KickAll()` 强制踢人的语义下是合理的（让客户端走异常路径而非优雅 EOF）

- 提问（Q13）：`HandleAsync(frame.Value, ...)` 为什么要 `.Value`，直接 `frame.Type` 不行吗
- 答复要点：`ReadFrameAsync` 返回 `ValueTask<Frame?>`，而 `Frame` 是 `readonly struct`，所以 `frame` 的静态类型是 `Nullable<Frame>`（另一个 struct），不是 `Frame`，成员访问报 CS1061。**核心洞察：值类型的 `T?` 改变的是类型，引用类型的 `T?` 改变的是标注**——所以 `if (frame is null) return;` 对 `Nullable<T>` 只做运行时保证，不做类型收窄，之后仍需 `.Value`。替代写法 `if (frame is not { } f) return;` 可一次完成判空 + 解包。另提醒不要用 `GetValueOrDefault()`（无值时静默产生 default(Frame)，Type=0 会流进 default 分支），`.Value` 的 fail-fast 才是对的

- 提问（Q14）：JSON 反序列化怎么知道每个字段占多少字节，`string` 是引用类型，连续字节怎么切分
- 答复要点：**不按长度切，按语法切**。`PayloadCodec.FromUtf8` 内部是 `JsonSerializer.Deserialize<T>(ReadOnlySpan<byte>, options)` 即 JSON 解析而非二进制拆包；JSON 自描述，字符串由双引号定界（转义在引号内处理）、字段由 `:` `,` 分隔、数字读到非法字符为止。**核心洞察：两层切分机制完全不同**——帧层用 16 字节头里的 `payloadLen` 长度前缀（不懂内容也能切 + 防长度攻击），负载层用 JSON 语法（灵活可读 + 字段可增删）。用户是把"二进制思维"套在文本格式上了；protobuf/MessagePack 才需要 length-prefix。另说明 `JsonSerializerDefaults.Web` 三项配置（CamelCase / 大小写不敏感 / 允许数字字符串）与 `Utf8JsonReader` 直读 UTF-8 避免中间 `string` 分配
