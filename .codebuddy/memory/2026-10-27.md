## 代码阅读辅导

用户已进入「第 1 轮：协议层」逐行阅读阶段，问的都是 C# 语言细节而非架构问题，说明按路线在读代码。

- 提问：`FrameCodec.Encode` 第 22 行 `WriteHeader(buffer, ...)` 传入 `byte[]` 给 `Span<byte> destination` 参数是否隐式转换
- 答复要点：是语言内建的隐式转换（`Span<T>.op_Implicit(T[]?)`），零拷贝视图，所以 `WriteHeader` 写入的就是 `Encode` 里的 `buffer` 本身；坑是 null 数组会转成空 Span 而不抛 NRE
- 后续若用户继续问语言细节，说明可以跳过架构讲解，直接进入断点追踪或改造练习
- 提问：`Frame.Payload` 为何用 `ReadOnlyMemory<byte>` / 是否「没有 readonly array 才将就」
- 答复要点：是三条约束的交集，不是退路——① `FrameReceived?.Invoke` 会广播给多个订阅者，`byte[]` 允许下游改写内容；② `FrameReader.ReadFrameAsync` 是 async，`Span<byte>` 是 byref-like（`ref struct`），不能做普通 struct 字段（CS8345）也进不了状态机；③ 需零成本 `.Span` 喂 `PayloadCodec.FromUtf8(ReadOnlySpan<byte>)`，`IReadOnlyList<byte>` / `ReadOnlyCollection<byte>` 都做不到
- 补充概念：byref-like = `ref struct`，实例只能上栈，禁止做类字段/装箱/数组元素/泛型实参/跨 await；`Memory<T>` 是「存得进字段的 Span」，内部仍包数组，不是数组的替代品
- 提问：`FrameCodec.WriteAsync` 第 102 行 `await stream.WriteAsync(buffer, cancellationToken).ConfigureAwait(false)` 的含义
- 答复要点：命中 `Stream.WriteAsync(ReadOnlyMemory<byte>, CancellationToken)` 重载（`byte[]` 隐式转 `ReadOnlyMemory`，返回 `ValueTask`）；`Stream.Write` 契约是成功即全量写出或抛异常，不像 `Socket.Send` 要自己循环补发；`ConfigureAwait(false)` 不捕获调用方 `SynchronizationContext`，避免死锁与多余线程切换，库代码应统一写（`FrameCodec` / `ClientSession` / `ClientConnection` / `RpcClient` 已一致），切主线程由 `MainThreadDispatcher` 单独负责

- 提问：`record` 关键字
- 答复要点：`Messages.cs` 的 5 个 DTO 全是位置参数形式 `public sealed record X(...)`，`ClientOptions` 是 `sealed record` + `init` 属性块。选型理由：值相等语义便于断言测试、init-only 保证发出后不可改写、一行定义一个 DTO、`sealed` 阻断继承避免 STJ 多态问题；`Frame` 则用 `readonly struct`（热路径、无需相等语义）。坑：`ServerNotice` 的 `Level = "info"` 默认值仅在 C# 调用时生效，对端 JSON 缺该字段时 STJ 传 `null` 而非 `"info"`

- 提问：什么是 DTO、EOF
- 答复要点：`Messages.cs` 里的 record 就是 DTO（Data Transfer Object，只装数据无行为，形状由线上契约而非业务规则决定），`Frame` 不是 DTO 而是协议帧的运行时表示，`PayloadCodec` 是二者的序列化边界；EOF 在 Socket 语境 = 对端关闭写方向（`Read` 返回 0），项目里刻意区分两种 EOF——帧边界上返 `null` 走优雅关闭，帧中间抛 `EndOfStreamException` 视为异常；RST 导致的 `IOException`（远程主机强迫关闭）不属于 EOF

- 提问：数组 / `Memory<T>` / `Span<T>` 三者的关系
- 答复要点：数组是**所有者**，`Memory<T>` 是「能上堆的视图」（内部存 object 引用 + index + length，GC 可追踪），`Span<T>` 是「只能留在栈上的视图」（内部存 byref + length）；转换只向下免费（`T[]` → `Memory` → `Span`），`Span` → `Memory` 不可能，这正是 `TryParse` 里 `ToArray()` 的根源。项目内分工：`Frame.Payload`=ReadOnlyMemory（跨 await）、`PayloadCodec.FromUtf8`/`Encode`/`WriteHeader`=Span（同步热路径）、`ReadFullyAsync`=Memory（async 读）、`Magic`=byte[]（曾被 CS9202 逼退）
- 性能要点：循环里不要直接索引 `Memory<T>`，先 `var span = mem.Span` 取出来，否则每次索引都要经过 `Span` 转换且丢失 JIT 的边界检查消除

- 提问（Q10）：`Stream` 从哪里来、作用是什么
- 答复要点：来自 `TcpClient.GetStream()` 返回的 `NetworkStream`（`ownsSocket: true`，对底层 `Socket` 的流式封装），客户端在 `ClientConnection` 构造函数、服务端在 `ClientSession` 构造函数各取一次并持有。价值在于依赖倒置——`FrameReader(Stream)` / `FrameCodec.WriteAsync(Stream, ...)` 只声明抽象类型，因此可塞 `MemoryStream` 做测试、套 `SslStream` 上 TLS（Lab-C6 零改动）、套压缩层；同时 `Stream` 契约保证全量写出、`Read` 返回 0 = EOF。已作为新增的「主题 F」写入复习文档
