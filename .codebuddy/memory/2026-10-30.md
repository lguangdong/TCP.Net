- 提问（Q22）：`case "--host" when i + 1 < args.Length:` 里的语法，包括 `args[++i]` 和 `options with {...}`
- 答复要点：
  - `case <模式> when <布尔表达式>:` = **常量模式 + case guard**（C# 7）。执行规则：模式不匹配则 guard **根本不求值**；模式匹配但 guard 为假则**继续尝试后面的 case**，不是跳出 switch
  - guard 的必要性：没有它会 `args[++i]` 越界抛 `IndexOutOfRangeException`
  - `args[++i]` 前缀自增「先加再取」，配合 `for (var i...)` 的 `i++` 天然实现「跳过已消费的值参数」。已给出 4 个参数的完整走查表
  - `options = options with { Host = ... }` 不是修改而是**重建并替换**（`ClientOptions` 是 `sealed record`，`Host` 是 `{ get; init; }`，直接赋值报 CS8852）
  - `break` 只跳出 switch，之后回到 for 的 `i++`
  - 顺带列出 switch 可用的其他模式（类型/null/关系/组合/var/丢弃），以及 `case "-h": case "--help":` 多标签共享 body 的写法
  - **两个隐患**：① `i` 在 case 内被修改是隐式契约，改成 foreach 就编译不过；② guard 为假时静默落到 default，报错信息会误导成"未知参数 --host"，更好的写法是把缺值单独判断并给出准确提示

- 提问（Q23）：`public void Start() => _runLoop ??= Task.Run(() => RunAsync(_shutdownCts.Token));`
- 答复要点：三层语法——① `=>` 表达式体方法（C# 6）；② `??=` null 合并赋值（C# 8），**右侧惰性求值**（左非 null 时根本不执行 `Task.Run`），实现「幂等启动」；③ `Task.Run(Func<Task>)` 有专用重载会 **unwrap**，返回的 Task 等 `RunAsync` 整个方法结束才完成（若包成 `Func<void>` 则外层 Task 立刻完成，`StopAsync` 等不到）。**两个隐患**：`??=` 编译成「读-判空-写」三步**非原子**，两线程同时调 `Start()` 会启动两个 `RunAsync`（状态机错乱 + 孤儿 Task），修法 `lock` / `LazyInitializer.EnsureInitialized` / `Lazy<T>`；`_shutdownCts.Token` 在 lambda **内部**取值，若 lambda 执行前 CTS 已被 Dispose 则抛 `ObjectDisposedException` 且成为未观察异常，应提前 `var token = _shutdownCts.Token;` 取出
- 提问（Q24）：一个请求挂起期间又来新请求，会不会在同一处挂起？是否不限制 `RequestAsync` 调用？
- 答复要点：**不会**。每次 `async` 调用生成**独立的状态机实例**，`seq`（`Interlocked.Increment`）、`pending`（新 `PendingRequest` + 独立 TCS）、`timeoutCts` 全是局部变量，只有 `_pending` 字典共享（用 seq 做 key 隔离）。唤醒靠 `OnFrameReceived` 里 `frame.Seq` 查字典配对，所以**响应可以乱序到达**——这正是 `Frame.Seq` 字段存在的理由。1000 个并发挂起 = 0 线程占用 + 1000 个状态机。三条隐含限制：Channel 容量 1024 会反压、每个请求有超时所以挂起数有上限、`finally` 里按 seq 清理不泄漏。对比「同步 RPC」加锁写法会退化成串行
- 提问（Q25）：`CancellationToken cancellationToken = default` 里 `default` 的含义
- 答复要点：`default` 是 C# 7.1 default 字面量 = `default(CancellationToken)` = `CancellationToken.None`，内部 `_source == null`，所以 `CanBeCanceled == false`、`IsCancellationRequested` 永远 false、`Register` 返回空注册——语义是「**永远不会被取消**」。让参数成为可选参数，调用方可以只写 `EchoAsync("hi")`。传进 `RequestAsync` 后，`catch (OperationCanceledException) when (!cancellationToken.IsCancellationRequested)` 恒为 true，因此任何取消异常都会被判定为超时并转 `TimeoutException`，符合预期。另提醒默认参数值在**调用方编译期固化**，改默认值后已编译的调用方不会更新
